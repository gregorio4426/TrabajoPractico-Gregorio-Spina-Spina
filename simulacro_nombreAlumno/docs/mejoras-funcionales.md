# Bloques, catálogo personalizado, objetivos y comentarios

**Actualización 007:** los pesos se configuran por asignación, no en escrituras de plantillas. Las sesiones guardan una copia histórica. Ver [pesos por asignación](../../frontend/PESOS-POR-ASIGNACION.md).

La migración aditiva `006_mejoras_funcionales.sql` se aplica después de 005, con escritores detenidos y copia de seguridad verificada. No borra ni reinterpreta rutinas, asignaciones, sesiones o series existentes. Puede repetirse y conserva valores ya registrados. Las instalaciones nuevas de Compose ejecutan todos los SQL; los volúmenes existentes requieren aplicar 006 explícitamente antes de arrancar la nueva API. No eliminar el volumen para actualizar.

## Contratos compatibles

- Cada prescripción de `dias[].ejercicios[]` admite `bloqueOrden`, `bloqueNombre` (100), `vueltas`, `ordenEnBloque`, `descansoEjercicioSegundos` y `descansoVueltaSegundos`. Un bloque de un ejercicio representa series; dos, biserie; más, circuito. No se limita la cantidad de ejercicios. Las vueltas coinciden con `seriesSugeridas`; cada ejercicio conserva sus propias repeticiones y peso. Los descansos son segundos enteros no negativos, opcionales. Los bloques comparten nombre, vueltas y descanso entre vueltas; sus posiciones no pueden repetirse. Los clientes anteriores pueden seguir enviando prescripciones planas. Editar crea una versión nueva; las asignaciones anteriores conservan su versión.
- `GET /api/grupos-musculares` lista el catálogo; `POST`, `PUT /{id}` y `DELETE /{id}` requieren PROFESOR, como la administración de ejercicios. Crear un nombre equivalente (acentos, mayúsculas, espacios) reutiliza el grupo. Los seis grupos estándar no se renombran/eliminan, por compatibilidad con clientes que usan el enum. Los personalizados se renombran manteniendo sus referencias y solo se eliminan sin ejercicios asociados.
- `EjercicioRequest` acepta `grupoId` o el enum previo `grupoMuscular`. La respuesta incluye `grupoId` y `grupoMuscularNombre`. Las prescripciones capturan el nombre del grupo para conservar su historia. Los nuevos nombres de ejercicio se normalizan para evitar duplicados; los duplicados legados no se eliminan automáticamente y admiten editar descripción/grupo manteniendo su nombre.
- `objetivoPersonalizado` es texto libre opcional de hasta 2000 caracteres, disponible en el perfil del alumno, seguimiento autorizado y administración. Se requiere una descripción no vacía o la categoría anterior. Omitir el campo conserva el valor existente; enviarlo vacío permite limpiarlo si hay categoría.
- `PUT /api/sesiones/{id}/completar` admite cuerpo opcional `{"comentario":"..."}` (hasta 2000). Solo el propietario finaliza una sesión abierta con al menos una serie válida. El comentario queda en `SesionResponse`, con `alumnoNombre`, y es visible mediante los mismos permisos del historial: propietario, profesores actualmente vinculados y ADMIN. No se agrega un permiso para editar comentarios cerrados.

## Verificación

Pruebas HTTP adicionales cubren persistencia de bloques, versiones históricas, objetivos libres, comentario opcional/largo/propietario, acceso de profesores vinculados y catálogo personalizado. Se mantiene la suite previa. La prueba MySQL valida 006 dos veces, conservación de registros y validación Hibernate. La ejecución completa con `MYSQL_TEST_URL` aprobó 213 pruebas, sin omisiones. Angular aprobó la compilación de producción y 113 pruebas unitarias/HTTP.

Chromium aprobó 55 pruebas sin omisiones con Angular en configuración de producción (47 con API real y 8 aisladas). El recorrido nuevo guarda una biserie con pesos cero/desconocido, recupera una sesión abierta, finaliza parcialmente y verifica el comentario desde el profesor vinculado. La construcción de las tres imágenes Docker también fue aprobada.
